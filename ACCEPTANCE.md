# Приёмка на Paper

Статус: на игровом сервере ещё не выполнена.

1. Чистый Paper 1.21.11 / Java 21: включение без ошибок, status = OPEN.
2. Закрыть на 30s; обычный тестовый игрок не входит, существующий игрок остаётся онлайн. После срока вход разрешён.
3. Проверить отдельно UUID-допуск, permission bypass и operator-bypass true/false. Не выполнять тест без доступа к консоли.
4. Проверить nick → UUID только для онлайн-игрока; неизвестный ник должен требовать UUID.
5. Запланировать короткое окно в будущем. Проверить время UTC, объявление начала, MOTD и открытие по окончании.
6. Перезапустить сервер посреди окна; срок не должен начинаться заново.
7. Проверить замену текущего окна новым будущим расписанием: до будущего начала вход открыт.
8. Проверить отказ другого плагина (бан или whitelist): MaintenanceGate не должен его снимать.
9. Два оператора одновременно меняют состояние: устаревшая ревизия отклоняется, потерянных записей нет.
10. Проверить вывод аудита, пагинацию, срок и ревизию подтверждения allow clear.
11. На копии данных повредить gate.dat и перезапустить. Обычный вход закрыт, status сообщает необходимость восстановления. Команды изменений не перезаписывают повреждённый файл.
12. На копии config.yml допустить ошибку запуска; проверить аварийное закрытие и восстановление после исправления и рестарта.
13. Проверить текущую систему разрешений: bypass должен определяться уже в PlayerLoginEvent.

После выполнения записать точную сборку Paper, список влияющих плагинов и фактические результаты. Наличие этого сценария не подтверждает его выполнение.
