# MaintenanceGate

Режим технических работ для Paper 1.21.11 / Java 21. Проект Warndev.

Плагин ограничивает новые подключения во время обслуживания. Поддерживает окно по расписанию, автоматическое окончание, допуск по UUID, отдельные права обхода и журнал последних изменений. Уже подключённые игроки остаются на сервере.

Версия 0.1.0. Сборка и автоматические тесты проверены; серверная приёмка пока не выполнена. См. [VERIFICATION.md](VERIFICATION.md) и [ACCEPTANCE.md](ACCEPTANCE.md).

## Установка

1. Соберите проект командой `mvn clean verify` на JDK 21 и Maven 3.9+.
2. Установите `target/MaintenanceGate-0.1.0.jar` в `plugins` тестового Paper 1.21.11.
3. Перезапустите сервер. Выполните `/mgate status` из консоли.
4. Проверьте `operator-bypass` в `plugins/MaintenanceGate/config.yml`. По умолчанию операторы допускаются.

Дополнительные плагины и базы данных не требуются. Все сообщения — обычный текст, без исполнения MiniMessage или команд из причины обслуживания.

## Команды

| Команда | Действие | Право |
|---|---|---|
| `/mgate help` | Справка | `maintenancegate.use` |
| `/mgate status` | Режим, ревизия, время и допуски | `maintenancegate.use` |
| `/mgate on 30m Обновление мира` | Закрыть вход на 30 минут | `maintenancegate.manage` |
| `/mgate on forever Обновление` | Закрыть до ручного открытия | `maintenancegate.manage` |
| `/mgate off` | Открыть вход и отменить окно | `maintenancegate.manage` |
| `/mgate schedule 2026-10-01T18:00:00Z 1h Обновление` | Заменить текущее окно запланированным | `maintenancegate.manage` |
| `/mgate allow add <UUID или точный онлайн-ник>` | Добавить допуск | `maintenancegate.allowlist` |
| `/mgate allow remove <UUID или точный онлайн-ник>` | Удалить допуск | `maintenancegate.allowlist` |
| `/mgate allow list [страница]` | Посмотреть UUID | `maintenancegate.allowlist` |
| `/mgate allow clear` | Получить код подтверждения очистки | `maintenancegate.allowlist` |
| `/mgate audit [страница]` | Последние изменения | `maintenancegate.audit` |
| `/mgate reload` | Перечитать сообщения и политику операторов | `maintenancegate.reload` |

Для всех команд нужно `maintenancegate.use`. Административные права по умолчанию доступны операторам. Право `maintenancegate.bypass` по умолчанию не выдаётся никому; операторский обход регулируется отдельным параметром `operator-bypass`.

Очистка допусков требует повторить команду с выданным кодом в течение 30 секунд. Код привязан к отправителю и ревизии состояния. После изменения состояния подтверждение нужно получить заново.

Длительности: `30s`, `10m`, `2h`, `1d`; максимум 30 дней. Начало расписания задаётся ISO-8601 с часовым поясом, обычно UTC с суффиксом `Z`, не дальше 30 дней в будущем. Пример даты выше нужно заменить будущей датой относительно текущего времени сервера.

Одновременно хранится **одно окно**. Команды `on`, `off`, `schedule` заменяют его. Планирование будущего окна во время активного обслуживания немедленно снимает текущее ограничение до нового начала. Это сознательная семантика замены: проверьте `/mgate status` перед изменением.

## Допуск игроков

Вход разрешён, если обслуживание не активно, UUID есть в списке, выдано `maintenancegate.bypass` или игрок является оператором при `operator-bypass: true`. Отказ другого плагина, уже установленный в PlayerLoginEvent, не отменяется.

Проверка выполняется при входе, а не постоянно для игроков онлайн. Плагин не кикает текущих игроков и не заменяет whitelist, баны, авторизацию или защиту прокси. Решение основано на UUID, который предоставляет сервер. В offline-mode безопасность личности игрока зависит от вашей системы авторизации и настройки прокси; MaintenanceGate не подтверждает владение аккаунтом.

Права обхода должны быть доступны вашей системе прав уже во время PlayerLoginEvent. Это нужно проверить при серверной приёмке. Допуск по UUID не требует загрузки офлайн-профиля и не обращается к внешним сервисам.

## Хранение и восстановление

Состояние находится в `plugins/MaintenanceGate/gate.dat`. В него входят окно обслуживания, до 512 UUID и последние 100 административных изменений. Каждое изменение получает возрастающую ревизию, время, UUID оператора и тип действия. Нулевой UUID обозначает консоль.

Запись выполняется отдельным потоком. Новое состояние начинает действовать после успешной записи. Данные записываются во временный файл, синхронизируются через FileChannel.force и заменяют основной файл атомарным перемещением. Файловая система должна поддерживать ATOMIC_MOVE. Предыдущее корректное состояние сохраняется в `gate.backup`.

Контрольная сумма обнаруживает повреждение файла, но не является защитой от администратора, способного его переписать. Гарантия сохранности при потере питания зависит также от файловой системы и оборудования; синхронизация каталога отдельно не выполняется.

Если несколько администраторов одновременно отправляют изменения одной ревизии, устаревший запрос отклоняется. Нужно проверить status и повторить команду. Ошибка записи сохраняет прежнее состояние в памяти. Очередь содержит не более 8 ожидающих изменений и одного выполняемого.

При повреждённом состоянии, пропавшем основном файле при наличии резервного или ошибке config.yml на запуске включается аварийное закрытие входа. Изменения заблокированы. В этом режиме операторы допускаются при аварийных настройках для ошибочного config.yml; при повреждении только gate.dat действует корректно загруженная политика обхода.

Для восстановления:

1. Остановите сервер и сохраните копию всей папки MaintenanceGate.
2. Исправьте config.yml, если причина в нём.
3. Если повреждён gate.dat, восстановите проверенную копию. `gate.backup` содержит предыдущее состояние и может иметь другое окно обслуживания. Копировать его поверх gate.dat следует только после осознанного выбора нужного состояния.
4. Если данные не нужны, переместите **оба** файла gate.dat и gate.backup в отдельный архив. Следующий запуск создаст пустое открытое состояние при первой команде изменения.
5. Запустите сервер, проверьте status из консоли и вход тестовых игроков.

Не редактируйте двоичный файл и не меняйте его во время работы. Перезагрузка сообщений командой reload не выводит плагин из аварийного режима: после исправления нужен перезапуск сервера.

## Время и сообщения

Начало включительно, окончание исключительно. Время хранится в UTC; после перезапуска окончание не отсчитывается заново. Плагин сравнивает окно с системными часами. Ручной перевод часов влияет на фактический режим; настройте синхронизацию времени сервера.

Ограничение входа и MOTD вычисляются по текущему времени при событии. Объявления о начале и окончании проверяются раз в 20 тиков и при лаге могут запаздывать. При запуске уже активного окна лишнее объявление не отправляется. Шаблоны поддерживают `{reason}` и `{end}`; подстановки внутри самой причины повторно не интерпретируются.

Поддержка Folia, прокси-плагина и других версий Paper не заявлена. Конфликты с плагинами, меняющими решение входа или MOTD после MaintenanceGate, необходимо проверить на вашей сборке.
